# NeuroGebra 3.0.0

**Release target: 3.0.0 · Prepared November 25, 2026.** Publication is a maintainer action; this page describes the source release and does not assert that it is already on PyPI.

NeuroGebra 3.0 makes the library easier to explore and fixes important edge cases in training, checkpointing and scientific experiments. The documentation now presents one coherent guide from an executable formula to an inspectable model.

## Highlights

- A classic documentation design with warm paper tones, teal accents, serif headings, light/dark themes, responsive navigation and local system fonts.
- Generated catalogs covering all 285 formulas and 48 dataset loaders, with return conventions and provenance.
- A fuller architecture guide, first program, capability matrix, troubleshooting, contributor guide, migration notes and technical review.
- Optimizer state survives model checkpoints for Adam, SGD and RMSprop, including custom hyperparameters and update buffers.
- Stable Dense softmax/cross-entropy training computes loss from logits and handles probability targets correctly.
- PINN residual gradients cover every weight and bias, including layers with more than 256 weights.
- Expression training reuses symbolic derivatives across steps rather than repeatedly differentiating and rebuilding numerical callables.

## Correctness fixes

PINN data gradients are normalized over all output elements. Vector targets for a single-output model are aligned deliberately; invalid shapes and configurations raise explicit errors. Residual callbacks accept either `(points)` or `(model, points)`, preserve internal `TypeError` exceptions, and restore perturbed parameters if evaluation fails.

Sparse categorical labels must be finite integers. Probability targets must be nonnegative and sum to one. The general softmax backward operation uses its true vector-Jacobian product; cross-entropy handling is an explicit fused path rather than a heuristic based on gradient magnitude. An empty metric selection remains empty.

C JIT uses portable compiler targets instead of forcing AVX2 based on architecture alone. Its cache key includes compiler identity; variables and optimization arguments are validated, and `NEUROGEBRA_CACHE_DIR` allows a writable cache root.

## Release engineering

The publication workflow verifies tag/package/runtime version agreement, runs tests, builds strict documentation, validates snippets and local links, builds distributions and smoke-tests the installed wheel before uploading. Failed or duplicate package uploads remain visible. Source distributions include the MkDocs configuration, theme override and validation scripts.

Pushing a branch or tag does not publish to PyPI. Publishing a GitHub release triggers the upload workflow; stable releases use the repository's `PYPI_TOKEN`, and prereleases use `TEST_PYPI_TOKEN` for TestPyPI.

## Upgrade notes

The [migration guide](migration-3.md) explains numerical behavior changes, old checkpoints and native backend compatibility. The core package still requires Python 3.9+. No claim of universal performance superiority over other ML frameworks is made in this release.

## Known boundaries

Neural models and PINNs train with NumPy. PINN residual differentiation is numerical and can be expensive. The CUDA path evaluates supported expressions and transfers host arrays per call. Framework bridge capabilities differ. Pickle checkpoints require trusted inputs, and scheduler/RNG state is not saved. See [capabilities](../project/capabilities.md) and the [review and roadmap](../project/review-3.md).
